# 叩き台の言葉を保ってスライドを整える

人間が書いた言葉を資料の基準にする。発表者が自分の言葉で話せるよう、内容と語り口を保ち、見た目と情報の配置を整える。

## 原稿の扱い

- 原稿の原本を残し、指定がなければ別ファイルにスライドを作る。既存資料の直接編集を依頼された場合は、その指定に従う。
- 原稿がまだなければ、叩き台の提示を求める。原稿の代わりとなる主張や構成を勝手に生成しない。
- 対象読者・持ち時間・出力形式・テーマは、原稿や作業先の設定、会話から読み取れるものを使う。制作を左右する不明点だけ確認する。
- 出力形式が未指定で既存設定もない場合は、編集しやすいMarpのMarkdownを初稿とし、その選択を伝える。指定された形式や既存資料の形式を優先する。

## 日本語をなるべく変えない

そのまま使える文章は、そのまま使う。見出しも原稿から選び、原文の言葉で内容を示す。

| 変更                                   | 基本の扱い                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------- |
| 改行、段落、文字の強調、余白           | 意味のまとまりを保って調整する                                             |
| 明らかな誤字・脱字、句読点             | 読みが一意な範囲で最小限直す。用語や数値の誤りと推測したものは別途指摘する |
| 箇条書きへの分割                       | 原文の文言と条件を残す                                                     |
| 要約、言い換え、見出しの新規作成       | 原文で収まる方法を先に試す。必要なら原文を残した初稿と別に提案する         |
| 主張・事例・結論の追加、話の順番の変更 | 依頼された場合に行う。自発的な案は本体に混ぜず提案にする                   |



- 話し言葉、本人らしい表現、具体的な動詞を残す。見栄えのために抽象語・標語・英語風の名詞表現へ置き換えない。
- 数値、単位、固有名詞、否定、条件、例外、留保を保つ。「できる場合がある」を「できる」にするなど、断定の強さを変えない。
- 文脈が曖昧な箇所は推測で埋めない。該当箇所を特定して確認事項にし、他の制作は進める。
- 日本語の推敲を別途依頼された場合も、その範囲だけ直す。文章改善の別スキルを使う場合、この依頼の原文保持の方針を引き継ぐ。

## 配置で読みやすくする

原稿の順番と説明のつながりを尊重し、意味の切れ目でページを分ける。ページ数やテンプレートの枠に合わせるために内容を削らない。

- 長い文章は、改行、配置の変更、ページ分割の順で対処する。文字を極端に小さくして詰め込まない。
- 詳細を発表者ノートへ移す場合は、投影だけで主要な意味と必要な条件が伝わるようにする。配布して読む資料では、必要な説明をノートだけへ移さない。
- 強調は原稿の主張を支える箇所に絞る。留保だけを小さく薄くして、主張の意味を変えない。
- 既存テーマがあれば尊重し、書体、色、余白、見出しの位置を揃える。全ページを同じカード配置へ押し込まない。

## ソフトバンク式の見せ方を取り入れる

前田鎌利氏が紹介する社内プレゼンの手法を、配置・強調の基本候補にする。適用時は[ソフトバンク式の実践指針](references/softbank-style.md)を読む。原文保持、ユーザー指定、既存テーマを優先し、型に合わせるための書き換えはしない。

- 1枚の中心メッセージを1つにする。複数あるときは原稿の意味の切れ目で分け、根拠や条件も対応するページに残す。
- 左にグラフや図、右にメッセージを置く配置から検討する。上下配置が適する場合はメッセージを上にする。
- 原稿に論理のつながりがある場合は、左の図から右上の説明、右下の結論へ視線を導く「逆L字」を使う。
- タイトルやキーメッセージの13文字以内は目安にする。原文が長ければ改行やページ分割で対応し、短縮案は別に示す。
- 白地・黒い文字・グレーの補助要素を基本候補とし、意味のある強調だけに色を使う。肯定的な意味に青、否定的な意味に赤を使い、色だけで意味を伝えない。
- 論理の接続に増減と紛らわしい下向き矢印を使わず、グレーの三角形や関係を明示したフローを検討する。
- アニメーションは基本的に使わず、説明に必要な場合だけ順次表示する。画面比率は既存資料や投影先に合わせ、4:3へ一律に変更しない。

## 図にしたほうが分かるところを図にする

図解は、原稿にある関係を見える形にするために使う。すべてのページを図にする必要はない。文章のまま伝わる箇所は文章を残す。

| 原稿にある内容           | 図解の候補               |
| ------------------------ | ------------------------ |
| 明示された手順・時系列   | フロー、タイムライン     |
| 共通の観点での比較       | 比較表、左右配置         |
| 全体と部分、所属・包含   | 構成図、入れ子           |
| 明示されたやり取り・接続 | 関係図                   |
| 実測値や集計値           | 単位と出典を添えたグラフ |

- 図中のラベルは原文の語句を使う。短縮で意味が落ちるなら、ラベルを改行するか、近くに原文の説明を置く。
- 単なる列挙に順序の矢印を足さない。関連を因果として描かない。矢印が何を示すのか分からない場合は、矢印を使わず並べるか確認する。
- 並列の項目に上下の序列や大小の重要度を勝手に付けない。強調色や図形の面積が意図しない評価を生まないか確認する。
- 説明に必要な条件や例外を図でも残す。原稿にないデータ、効果、登場人物、関係を加えない。
- 図の文字は編集できるテキストにする。形式が許せば図形やSVGを使い、日本語の文章全体を画像生成で描かせない。

例：原文が「申請内容を確認してから、担当者に送る。急ぎの場合は先に電話する。」なら、通常手順のフローに加えて「急ぎの場合は先に電話する」を条件として表示する。例外を落とした一本道の図にはしない。

## 制作と確認

このスキルは原稿の扱いを定める。実際の制作・書き出しには、指定された形式に対応する利用可能なスキルやツールを使う。別スキルの構成・演出・文章改変の提案を自動採用せず、今回の依頼と原文保持の方針に合わせて判断する。

完成前に、次の両方を確認する。

1. **原稿との照合**：本文、図のラベル、ノートを原稿と照合し、内容の欠落、主張の追加、条件や否定の変化、図だけに生じた関係がないか確認する。誤字修正を除く言い換えや削除があれば、元の表現に戻すか、依頼された変更として説明できるか確かめる。
2. **表示の確認**：作成した形式を実際に描画して、文字切れ、重なり、読みづらい小さな文字、図の接続、改行、ページ間の統一感を確認する。描画できなかった場合は、目視確認済みと報告しない。

成果物とともに、配置・分割・図解で整えた点を短く伝える。文言を変えた場合は、誤字・句読点などの軽微な修正をまとめ、それ以外は原文と変更後が分かる形で示す。未解決の確認事項と未実施の検証があれば明記する。提案だけで終えず、依頼された成果物を作成する。
