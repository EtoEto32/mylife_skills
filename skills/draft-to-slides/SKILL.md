# 叩き台の言葉を保ってスライドを整える

人間が書いた言葉を資料の基準にする。発表者が自分の言葉で話せるよう、内容と語り口を保ち、見た目と情報の配置を整える。

## 目的と適用範囲

| 項目 | 定義 |
| --- | --- |
| purpose | 学会発表・ゼミ資料・LTなどで使える、分かりやすい資料を作る |
| trigger | 叩き台のプレゼンのデザイン性・視認性・分かりやすさを改善する依頼 |
| boundary | 構成からデザインまで、一からスライドを作る依頼には使わない |
| input | 人間が作った叩き台のPPTX形式のプレゼン資料 |
| output | 原文をなるべく保ち、自然で統一感のあるデザインに整えたPPTX形式のプレゼン資料 |
| validation | PPTXを完成させ、原稿との照合と全スライドの表示確認を通す |

ここでいう「自然なデザイン」は、用途に合った情報の強弱があり、書体・色・余白・整列に統一感があり、装飾が説明を妨げない状態を指す。学会・ゼミでは図表、式、引用、研究上の留保を保ち、LTでも主張や本人の語り口を削らない。

## 入力PPTXの扱い

- 入力PPTXの原本を残し、指定がなければ同じ作業先に別名のPPTXを作る。既存資料の直接編集を依頼された場合は、その指定に従う。
- 入力PPTXがまだなければ提示を求める。テーマだけから構成や内容を新規生成せず、一から作る依頼は適切な別の制作手順へ渡す。
- 最初に全スライドの表示と内容を読み、本文、図表、発表者ノート、画面比率、テーマを確認する。利用可能なPowerPoint編集ツールと対応するプレゼンテーション用スキルを使う。
- 対象読者・持ち時間・テーマは、資料や作業先の設定、会話から読み取れるものを使う。制作を左右する不明点だけ確認する。
- 完成品はPPTXとする。Markdown、HTML、PDF、プレビュー画像は必要に応じた補助成果物とし、それだけで納品を終えない。
- 本文と新しく作る図は、可能な限りPowerPointで編集できるテキスト・図形・グラフで残す。スライド全体を画像として貼り直す方法は避ける。既存の画像や研究図は必要に応じてそのまま利用する。

## 日本語をなるべく変えない

そのまま使える文章は、そのまま使う。見出しも原稿から選び、原文の言葉で内容を示す。

| 変更                                   | 基本の扱い                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------- |
| 改行、段落、文字の強調、余白           | 意味のまとまりを保って調整する                                             |
| 明らかな誤字・脱字、句読点             | 読みが一意な範囲で最小限直す。用語や数値の誤りと推測したものは別途指摘する |
| 箇条書きへの分割                       | 原文の文言と条件を残す                                                     |
| 要約、言い換え、見出しの新規作成       | 原文で収まる方法を先に試す。必要なら原文を残した初稿と別に提案する         |
| 主張・事例・結論の追加、話の順番の変更 | 依頼された場合に行う。自発的な案は本体に混ぜず提案にする                   |



- 話し言葉、本人らしい表現、具体的な動詞を残す。見栄えのために抽象語・標語・英語風の名詞表現へ置き換えない。
- 数値、単位、固有名詞、否定、条件、例外、留保を保つ。「できる場合がある」を「できる」にするなど、断定の強さを変えない。
- 文脈が曖昧な箇所は推測で埋めない。該当箇所を特定して確認事項にし、他の制作は進める。
- 日本語の推敲を別途依頼された場合も、その範囲だけ直す。文章改善の別スキルを使う場合、この依頼の原文保持の方針を引き継ぐ。

## 配置で読みやすくする

原稿の順番と説明のつながりを尊重し、意味の切れ目でページを分ける。ページ数やテンプレートの枠に合わせるために内容を削らない。

- 長い文章は、改行、配置の変更、ページ分割の順で対処する。文字を極端に小さくして詰め込まない。
- 詳細を発表者ノートへ移す場合は、投影だけで主要な意味と必要な条件が伝わるようにする。配布して読む資料では、必要な説明をノートだけへ移さない。
- 強調は原稿の主張を支える箇所に絞る。留保だけを小さく薄くして、主張の意味を変えない。
- 既存テーマがあれば尊重し、書体、色、余白、見出しの位置を揃える。全ページを同じカード配置へ押し込まない。

### プロジェクター・大型スクリーン投影の文字サイズ

講演会・セミナーなどの投影資料は、次のPowerPoint上のポイント数を基準にする。用途が不明な場合も、発表用PPTXにはこの基準を適用する。ユーザーから別の指定がある場合は、その指定を優先する。

| 要素 | 文字サイズの基準 |
| --- | --- |
| スライドタイトル・大見出し | 36〜50pt以上。44ptを基本とし、長い場合もまず改行や配置を調整する |
| 中見出し | 24〜32pt |
| 本文 | 24〜28pt以上を目標とする。20ptを下限の目安とし、例外的に調整する場合も18pt未満にしない |
| 図中ラベル・表のセル・グラフの軸や凡例 | 内容の理解に必要な文字は本文と同じ基準で設計する |

- 収まらない場合は、図解、配置変更、意味の切れ目でのページ分割で解決する。自動縮小や図全体の縮小で基準を下回らせない。
- 出典・ページ番号は本文と区別する。ただし説明に必要な条件・留保・単位を、小さな注記にして逃がさない。出典も実際の投影で判読できる大きさにする。
- 編集APIの単位を確認する。CSS pxを使うAPIでは `pt × 96 / 72` で換算し、44pxを44ptとして扱わない。最終PPTX内の実効フォントサイズも確認する。

### 余白と画面全体のバランス

- 関連する説明と図を近づけ、意味のまとまりの間に余白を置く。空行や巨大なテキスト枠で位置を作らない。
- 上や左に小さく内容を寄せたまま、下や右に理由のない大きな空白を残さない。本文・図の拡大、左右・上下の再配置で、画面全体の重心を整える。
- 図中ラベルと対象、見出しと本文、図とキャプションの距離を確認する。離れすぎた説明や不自然な段落間隔を直す。
- 全オブジェクトを一律に縮小して枠内に収めない。回転した図形、見えない枠、空のプレースホルダーを含む外接矩形だけで配置を決めず、実際に見える文字と図の範囲で判断する。
- 余白を埋めるためだけの装飾や文章は足さない。表紙・章扉・短いメッセージの意図的な余白は残す。

## ソフトバンク式の見せ方を取り入れる

前田鎌利氏が紹介する社内プレゼンの手法を、配置・強調の基本候補にする。適用時は[ソフトバンク式の実践指針](references/softbank-style.md)を読む。原文保持、ユーザー指定、既存テーマを優先し、型に合わせるための書き換えはしない。

- 1枚の中心メッセージを1つにする。複数あるときは原稿の意味の切れ目で分け、根拠や条件も対応するページに残す。
- 左にグラフや図、右にメッセージを置く配置から検討する。上下配置が適する場合はメッセージを上にする。
- 原稿に論理のつながりがある場合は、左の図から右上の説明、右下の結論へ視線を導く「逆L字」を使う。
- タイトルやキーメッセージの13文字以内は目安にする。原文が長ければ改行やページ分割で対応し、短縮案は別に示す。
- 白地・黒い文字・グレーの補助要素を基本候補とし、意味のある強調だけに色を使う。肯定的な意味に青、否定的な意味に赤を使い、色だけで意味を伝えない。
- 論理の接続に増減と紛らわしい下向き矢印を使わず、グレーの三角形や関係を明示したフローを検討する。
- アニメーションは基本的に使わず、説明に必要な場合だけ順次表示する。画面比率は既存資料や投影先に合わせ、4:3へ一律に変更しない。

## 図にしたほうが分かるところを図にする

各ページで、文章のまま示す場合と図表にする場合の分かりやすさを比較し、図表のほうが関係や違いを素早く理解できる箇所は積極的に図表へ置き換える。既存の図を整えるだけで終えず、文章中心のページも図解候補として検討する。原文保持は、文章の配置や形式を固定することではない。原文の語句と条件を使って図表に組み替えることは、このスキルの作業範囲に含む。

すべてのページを図にする必要はない。文章のまま伝わる箇所は文章を残す。

| 原稿にある内容           | 図解の候補               |
| ------------------------ | ------------------------ |
| 明示された手順・時系列   | フロー、タイムライン     |
| 共通の観点での比較       | 比較表、左右配置         |
| 全体と部分、所属・包含   | 構成図、入れ子           |
| 明示されたやり取り・接続 | 関係図                   |
| 実測値や集計値           | 単位と出典を添えたグラフ |
| 仕様・属性・設定値の列挙 | 項目と値を対応させた表   |
| 課題と対応策、入力と出力 | 対応関係を示す図・対比表 |

- 図中のラベルは原文の語句を使う。短縮で意味が落ちるなら、ラベルを改行するか、近くに原文の説明を置く。
- 単なる列挙に順序の矢印を足さない。関連を因果として描かない。矢印が何を示すのか分からない場合は、矢印を使わず並べるか確認する。
- 並列の項目に上下の序列や大小の重要度を勝手に付けない。強調色や図形の面積が意図しない評価を生まないか確認する。
- 説明に必要な条件や例外を図でも残す。原稿にないデータ、効果、登場人物、関係を加えない。
- 図の文字は編集できるテキストにする。形式が許せば図形やSVGを使い、日本語の文章全体を画像生成で描かせない。
- 図解後も投影用の文字サイズを守る。図や表が密になる場合は、関係が伝わる単位で分割し、ラベルを小さくして詰め込まない。

例：原文が「申請内容を確認してから、担当者に送る。急ぎの場合は先に電話する。」なら、通常手順のフローに加えて「急ぎの場合は先に電話する」を条件として表示する。例外を落とした一本道の図にはしない。

## 制作と確認

このスキルは既存PPTXの改善方針を定める。実際の編集・書き出しには、PPTXに対応する利用可能なスキルやツールを使う。別スキルの構成・演出・文章改変の提案を自動採用せず、今回の依頼と原文保持の方針に合わせて判断する。

編集開始時に[PPTXの書き出しと表示確認](references/pptx-export-validation.md)を読む。代表ページの無編集の読み込み・書き出しで、テーマ継承、図表、ノート、リンクが保持されるか先に確かめる。崩れる場合は全面変換を続けず、原本を基準に編集対象を絞る方法や別の編集手段へ切り替える。

完成前に、次を確認する。

1. **原稿との照合**：本文、図のラベル、ノートを原稿と照合し、内容の欠落、主張の追加、条件や否定の変化、図だけに生じた関係がないか確認する。誤字修正を除く言い換えや削除があれば、元の表現に戻すか、依頼された変更として説明できるか確かめる。
2. **表示の確認**：書き出したPPTXを開き直すか対応ツールで描画し、全スライドで文字切れ、重なり、読みづらい小さな文字、図の接続、改行、書体・色・余白・整列の統一感を確認する。タイトル・本文・図表ラベルの実効文字サイズを上記の基準と照合し、不自然な空白や説明と図の離れすぎも直す。文章中心のページで図表にしたほうが理解しやすい箇所が残っていないか見直す。修正したページは再確認する。編集途中のプレビューだけで完成判定をしない。
3. **成果物の確認**：完成したPPTXが存在し、読み込めることを確認する。本文、新規図解の編集可能性と、既存の図表・引用・ノートに意図しない欠落がないかも確認する。

原文の照合、PPTXの構造検査、描画の確認は別々に行う。文字数や自動検査の合格だけで表示の正常さを判断しない。改行後の余計な箇条書き、段落間隔の継承、一文字だけの折り返しを確認し、修正した場合は納品する最終PPTXを再描画する。自動警告は該当ページを確認し、実際の崩れ、枠だけの重なり、未確認に分けて扱う。

表示確認やPPTXの読み込みを実行できなかった場合は、確認できた範囲と未検証の点を示し、検証済みの完成品として報告しない。

成果物とともに、配置・分割・図解で整えた点を短く伝える。文言を変えた場合は、誤字・句読点などの軽微な修正をまとめ、それ以外は原文と変更後が分かる形で示す。未解決の確認事項と未実施の検証があれば明記する。提案だけで終えず、依頼された成果物を作成する。
